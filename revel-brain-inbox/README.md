# Revel Brain Inbox

The one place to send anything the Revel Wellness Brain should know: spec sheets, tech packs,
compliance certificates, manuals and corrections. Live at
`https://the-afs-group.github.io/revel-brain-inbox/` once `config.js` has its endpoint.

Three ways in. Each one gets a reference (BRAIN-0001), lands in the private Drive folder and the
tracker Sheet, emails the approvers, and sends the sender a receipt:

| Route | How | Best for |
|---|---|---|
| Upload page | `index.html`: note + any number of files (25 x 25 MB) | Sales, CS, showroom, offshore team |
| Email | Attach files to an email to the intake address | Anyone, from their phone or inbox |
| Drive folder | Drop files in **Revel Brain Inbox / Drop files here** | Product and supplier updates |

Then every 10 minutes the Apps Script sends new submissions to the private `revel-brain` repo. It
commits the files and opens a `brain-inbox` issue, and Claude drafts the card as a pull request for
Tristan and Ben. GitHub reports back to the Apps Script, which updates the tracker and emails people.

## Who gets emailed

| When | Approvers (`NOTIFY_EMAILS`) | Sender |
|---|---|---|
| New submission (any route) | Details, note, links to every file | Receipt with the reference and tracker link |
| Claude's draft is ready | **"Ready for your approval"** with the GitHub link | "In review" |
| Approved and merged | | "Live" |
| Closed without merging / already covered | | "Not accepted" / "No change needed" |
| Something failed | "Needs attention" | |
| Mondays | Weekly digest of everything waiting | |

The uploaded documents themselves never go into this public repo. They go to Drive, and then to
the private Brain repo.

## Files

| File | What it is |
|---|---|
| `index.html` | Upload page and tracker (Submit / Track tabs) |
| `config.js` | The only file to edit after setup: the Apps Script `ENDPOINT` |
| `products.js` | Product list for the picker. Generated by `_revel-brain/scripts/import_spec_sheet.py` |
| `apps-script/Code.gs` | Backend: Drive, tracker Sheet, Gmail intake, emails, GitHub hand-off |

## One-time setup (about 20 minutes)

Use the Google account whose Gmail should receive the emailed documents: the email route reads
that account's inbox. Ben's account is the natural choice.

1. **Sheet.** In Google Drive, create a Google Sheet called *Revel Brain Inbox*. Open
   **Extensions > Apps Script**, replace the code with `apps-script/Code.gs`, and save.
2. **Settings.** In **Project Settings > Script properties**, add:

   | Property | Value |
   |---|---|
   | `TEAM_CODE` | A code staff type once on the page (pick something you can say out loud) |
   | `NOTIFY_EMAILS` | Ben's and Tristan's work emails, comma separated |
   | `INTAKE_ADDRESS` | Where staff email documents. Easiest: this account's plus address, e.g. `firstname+brain@revelsaunas.com` (works in Google Workspace with no admin setup). Or a Google Group like `brain@revelsaunas.com` that delivers to this account |
   | `ALLOWED_DOMAINS` | Sender domains accepted by email, e.g. `revelsaunas.com`. Add the offshore team's domain if it's different. Anything else is labelled *Brain Inbox/Rejected* and ignored |

3. **Run `setup`** from the editor and approve the permissions (Sheets, Drive, Gmail, send email,
   external requests). It creates the tabs, the *Revel Brain Inbox* Drive folder with *Drop files
   here* and *Submissions*, the Gmail labels, a 10-minute trigger, and a `STATUS_TOKEN`. The log
   shows the folder links and the token.
4. **Share the drop folder.** Share *Drop files here* with staff as Editor. Keep the parent folder
   and *Submissions* to Ben and Tristan.
5. **Deploy.** **Deploy > New deployment > Web app**, Execute as **Me**, access **Anyone**. Copy the
   `/exec` URL into `config.js` as `ENDPOINT`, commit and push. After any later change to `Code.gs`, use
   **Deploy > Manage deployments > Edit > New version** so the URL stays the same.
6. **Test.** Run `testSubmission` in the editor: both approvers should get *[Brain] New submission*
   and the account owner a receipt. Then open the page, enter the team code and send a real file.
   Email a file to the intake address and wait up to 10 minutes.

Until GitHub is connected, everything collects in Drive and the tracker, and the emails still go out.

## Connecting the private Brain repo

Once `The-AFS-Group/revel-brain` exists (`_revel-brain/scripts/bootstrap.sh`):

1. Create a **fine-grained personal access token** on GitHub (Settings > Developer settings): resource
   owner *The-AFS-Group*, repository *revel-brain* only, permissions **Contents: Read and write** and
   **Issues: Read and write**. An org owner may need to approve it.
2. Add Script properties `GITHUB_TOKEN` (the token) and `GITHUB_REPO` (`The-AFS-Group/revel-brain`).
3. In the `revel-brain` repo, add Actions secrets `BRAIN_INBOX_URL` (the `/exec` URL) and
   `BRAIN_INBOX_STATUS_TOKEN` (the `STATUS_TOKEN` from step 3).
4. Run `checkSettings` in the editor. Everything should say OK.

## The "Ask Claude" route

The Brain chatbot ends any "add this to the Brain" request with a pre-filled link to this page:

```
https://the-afs-group.github.io/revel-brain-inbox/?channel=ask-claude&product=Kora%202P%20(Next%20Gen)&topic=Electrical&note=...
```

Supported parameters: `product` (full or short name; unknown names go in "New product"),
`topic`, `note`, `markets` (e.g. `AU,NZ`), `doctype`, `channel=ask-claude`.

## Security notes

- The page is public (`noindex`), but nothing works without the team code, which is checked by the
  Apps Script and isn't in the page source. Change `TEAM_CODE` to lock out old devices.
- The tracker shows reference, first name, product, topic and status only, never emails.
- GitHub gets the submitter's name and team, never their email.
- `STATUS_TOKEN` only lets GitHub post status updates and the digest. It can't read anything.
